# Go Learning Lab: Investment Ledger

Учебный репозиторий для повторного изучения Go, разработки одного сквозного проекта и постепенного восстановления понимания ShareTrip.

Разрабатываемый учебный продукт меняет предметную область с MeetupLite на **Investment Ledger** — backend для учёта операций и состояния инвестиционного портфеля. ShareTrip при этом не исключается: он остаётся обязательным проектом для чтения, восстановления цепочек вызовов и сопоставления архитектурных решений. Образовательная лестница остаётся прежней: чистый Go → ошибки и границы → интерфейсы и тесты → HTTP → PostgreSQL и согласованность → эксплуатация.

Цели — выпустить объяснимый и демонстрируемый `v1.0.0` до **30 ноября 2026 года** и восстановить понимание одного сквозного сценария ShareTrip от HTTP-входа до хранения данных. Декабрь предназначен для исправлений, демонстраций, подготовки к интервью и откликов.

## Что войдёт в v1.0

- портфель, счёт и финансовый инструмент;
- append-only операции Must: пополнение, вывод, покупка и продажа;
- cash balance, позиции, средняя стоимость, рыночная и общая стоимость, нереализованный P&L;
- ручные котировки и сводка текущего состояния портфеля;
- идемпотентная запись операций;
- read-only demo data и защищённый API key доступ к операциям записи;
- HTTP API, PostgreSQL, миграции и интеграционные тесты;
- Docker, CI, структурированные логи, метрики, health checks и развёрнутое демо.

Исторический `as_of`, reversal, дивиденды и комиссии относятся к Should-scope: они войдут в релиз только после зелёного Must-scope. CSV, Fiber, gRPC, outbox и OpenTelemetry остаются timeboxed labs и не блокируют `v1.0`.

Первая версия использует одну базовую валюту: валюта каждого инструмента, котировки и операции должна совпадать с валютой портфеля. Деньги нельзя хранить в `float64`: представление и правила округления выбираются в доменной модели на этапе 2, а на этапе PostgreSQL для них подбирается точное SQL-отображение.

## Что не войдёт в v1.0

- реальные сделки и хранение брокерских ключей;
- realtime-котировки и обязательная внешняя интеграция;
- налоги, налоговые лоты и корпоративные действия;
- мультивалютность;
- регистрация пользователей и полноценная ролевая модель;
- полноценный учёт бытовых расходов и бюджетов;
- frontend, микросервисы, Kafka и Kubernetes.

Эти ограничения защищают ноябрьский релиз от разрастания. Учёт личных финансов можно добавить после него вторым вертикальным сценарием.

## Правила обучения

- Один урок — одна основная идея и один небольшой коммит.
- Сначала самостоятельная попытка, затем вопрос-подсказка, псевдокод и только потом разбор решения.
- Готовый код не переносится из ShareTrip в Investment Ledger.
- Каждый новый механизм нужно уметь объяснить без открытого редактора.
- Стандартная библиотека изучается раньше Fiber и других фреймворков.
- Внешняя инфраструктура появляется только после работающего in-memory варианта.
- Каждая тема завершается тестом или другой воспроизводимой проверкой.
- Для конкурентного кода обязательна проверка race detector.
- Технология добавляется под конкретную задачу, а не ради списка в резюме.

## Роль ShareTrip

Investment Ledger — проект, в котором новый код пишется самостоятельно. ShareTrip — параллельный read-only трек для восстановления уже существующей системы. После каждого учебного этапа нужно:

1. Найти в ShareTrip соответствующий механизм.
2. Проследить, кто кого вызывает и как движутся данные и ошибки.
3. Сравнить решение с Investment Ledger без копирования реализации.
4. Записать выводы, непонятные места и технические компромиссы.

К ноябрю результатом станет карта одного use case ShareTrip: HTTP/gRPC-вход → application/use case → repository → PostgreSQL или внешний adapter → ответ и наблюдаемость.

## Текущее состояние

- Этап 1 «Базовый язык» завершён.
- Этап 2 «Ошибки и границы» начат: пройдены обычные и sentinel errors.
- Консольный пример перенесён в инвестиционный домен без добавления новой архитектурной сложности.
- Следующий урок: оборачивание ошибок через `%w`.

Запуск текущего примера:

```bash
go run .
```

Подробная последовательность, календарь и критерии готовности находятся в [LEARNING_PLAN.md](LEARNING_PLAN.md).

## Ориентиры программы

Публичный README [Job4j Go Lang Base](https://github.com/peterarsentev/job4j_go_lang_base) заявляет основы Go и инструменты, тесты, PostgreSQL/PGX, HTTP/Fiber, gRPC/Proto и архитектурные принципы; на официальной странице [программ Job4j](https://job4j.ru/programs) для основ Go также указаны ошибки, интерфейсы и goroutines. Полный порядок закрытых заданий публично недоступен, поэтому это ориентир, а не попытка дословно скопировать курс.

Этот репозиторий сохраняет ту же практическую логику, использует Investment Ledger вместо ShareTrip как проект для самостоятельной разработки и одновременно сохраняет ShareTrip как обязательный объект разбора. Дополнительно включены темы, необходимые для production-like backend: конкурентность, SQL и индексы, безопасность, Docker/CI, наблюдаемость, профилирование и деплой.
