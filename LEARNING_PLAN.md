# План обучения

## Как проходит каждый урок

1. Коротко воспроизводим предыдущую тему по памяти.
2. Формулируем одну новую идею простыми словами.
3. Сначала пишем небольшой пример самостоятельно.
4. Запускаем код и разбираем результат или ошибку.
5. Добавляем проверку либо тест.
6. Фиксируем одним небольшим коммитом.
7. Записываем, что уже можно повторить без подсказки.

## Этап 1. Базовый язык

1. Пакеты, `package main`, импорты и точка входа.
2. Переменные, константы, базовые и именованные типы.
3. Функции, параметры, несколько возвращаемых значений.
4. `if`, `switch`, `for`.
5. Массивы, slices и maps.
6. Структуры и методы.
7. Указатели и изменение состояния.

Контрольная работа: небольшая консольная программа без внешних зависимостей.

## Этап 2. Ошибки и границы

1. Значение `error` и линейная обработка ошибок.
2. Sentinel errors.
3. Оборачивание через `%w`.
4. `errors.Is` и `errors.As`.
5. Валидация данных на границе программы.
6. `defer` и освобождение ресурсов.

Контрольная работа: модель встречи с валидацией и понятными ошибками.

## Этап 3. Интерфейсы и тестирование

1. Неявная реализация интерфейсов.
2. Интерфейс рядом с потребителем.
3. In-memory repository.
4. Dependency injection без фреймворка.
5. Обычные и табличные тесты.
6. Тестовые реализации зависимостей.

Контрольная работа: создание, получение и публикация встречи полностью в памяти.

## Этап 4. HTTP

1. `net/http` и жизненный цикл запроса.
2. JSON DTO и преобразование в модель.
3. HTTP-коды и отображение ошибок.
4. `context.Context`.
5. Тестирование обработчиков через `httptest`.

Контрольная работа: HTTP API MeetupLite без базы данных.

## Этап 5. Хранение и согласованность

1. PostgreSQL и PGX.
2. Миграции.
3. Repository adapter.
4. Транзакции.
5. Конкурентное изменение состояния.
6. Transactional outbox.

## Этап 6. Эксплуатация

1. Структурированные логи.
2. Correlation ID.
3. Counter и histogram.
4. Prometheus и Grafana.
5. Сопоставление MeetupLite со слоями ShareTrip.

## Тема считается усвоенной, если

- её можно объяснить без открытого кода;
- уменьшенный пример получается написать самостоятельно;
- понятно, кто вызывает функцию и что она возвращает;
- можно предсказать, в каком месте возникнет ошибка;
- есть тест, подтверждающий ожидаемое поведение.
